# 扑飞与哔哩空响应、断连修复（2026-10-01，1.1.1）

手机反馈：扑飞进入《我家老婆来自一千年前》时显示 `cannot read property 'includes' of null at html (source.js:95)`，或 `connection closed`；哔哩也出现类似问题。此前的断连处理只覆盖 Chromium → OkHttp，已选择 OkHttp 的请求没有反向回退；HTTP 200 空响应也可能进入脚本。此前站点链路测试通过，不能证明上述失败响应与手机路由组合已覆盖。

本轮对扑飞、哔哩的 GET 请求增加两种传输之间的双向重试。配置系统 HTTP 代理时优先使用遵循代理的 OkHttp，其他情况使用原路由。完整读取响应体后才记录成功；空响应、响应未读完、403／429／5xx 可切换另一传输。空响应重试添加防缓存参数，重试刷新 Cookie，且总共仅尝试两次；源层不再重复执行整段脚本产生额外网络重试。两种传输均失败时返回可读错误，不将 null 当作成功页面。

扑飞 HTML 使用文本请求，由原生端根据响应头／HTML 声明处理 GBK、GB2312、GB18030 或 UTF-8；移除整个 HTML 的 Base64／JS 字节缓冲转换及可能对 null 调用的 includes。扑飞与哔哩脚本分别升级至 1.0.1、1.1.2，均校验页面正文。哔哩搜索票据兑换允许空 200，因为这是站点有效协议的一部分，不能当作失败重试。

新版应用版本为 1.1.1／199，源列表版本读取实际脚本版本。其余源的 GET 策略与 POST 流程保持原行为；此前漫画阅读加载策略未改动。本轮六个小说界面／元数据／Z-Library 文件与前次修复发布时散列相同，没有修改小说下载、登录或更新导入器。
