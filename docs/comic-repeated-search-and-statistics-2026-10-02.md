# 连续漫画搜索与阅读明细修复（2026-10-02）

原有 20 个漫画源全部逐一测试，爱看漫因反复超时及阅读断连暂时从默认列表下架，保留缓存和账号数据。最终保留的 19 个源中，19 个三次直接搜索均有结果，19 个完成详情、章节、页列表与首张图片解码；19 个重复查询在本轮 60 秒缓存内用时不超过 2ms。

保持八路跨站搜索；同一源的聚合、单源、阅读明细补查共用串行调度，完成后间隔 1.1 秒。非空成功结果缓存 60 秒，每源最多 8 个关键词；空结果及错误不缓存，替换源实例后旧结果失效。冷却不占跨站槽位，切换词会取消旧搜索。网站自身的限制无法由客户端通用取消；缓存和请求合并减少实际访问次数。

## 具体修复

- 取消旧 JS 搜索后，真实调用方 Job 仍用于取消网络、延时及脚本；在同源互斥锁内等待 native promise 收尾，再恢复取消的内部 scope、防御性清理已完成任务。首次取消时仍完成一次性 guard 注册并保留原 runtime。适配器只针对固定 QuickJS alpha13，现有 ProGuard 规则保留其字段。
- 全局高风险正则每批最多匹配 128 次，捕获累计 64Ki 字符后结束一批；保留 index、捕获组、lastIndex 与手动重置行为，继续执行 500ms 正则预算。减少每次 exec 都把同一网页全文传给 JNI 的临时对象，修复全源密集搜索时的 Java 堆耗尽。
- 有界的 Acorn 语法解析使用自身正则，AST 遍历每 64 节点检查预算，减少八个源同时初始化的跨 JNI 调用；实际源脚本的函数、循环、catch 入口仍逐次检查取消与运行预算。
- DOM 最多保留 8 文档 / 4MiB 估算体积；释放文档时清除关联元素和节点句柄，避免 Jsoup 树继续被引用。超大输入明确返回错误。
- 爱看漫 GET 与公开 read/pics 表单 POST 支持完整响应后的传输回退；对已验证官方公共入口可在代理失败后尝试同地址直连，成功路径保存 5 分钟，失败立即失效。登录 POST 不重放。修复后仍无法稳定使用，默认仓库列表排除 `ikmmh`，补丁版本为 38；未删除用户数据。
- hitomi 在完整词成功返回空列表时再尝试末尾括号之前的社团名，错误保留错误；截图中社团的括号别名 fixture 与实网查询均检查。
- 阅读时存原源 ID、资源 ID、封面、作者和记录 ID；明细优先用本地书、目的地快照、唯一同名收藏，立即逐条发布。旧记录才并行补搜，最多三个标题 / 四个请求，严格完整标题匹配，首命中取消其余，取消“只处理前五条”的限制。
- 明细封面共用书库 Coil 缓存、Cookie、源请求头与 Z-Library 加载器；日明细和周图均可打开原阅读目的地。新记录无需为了找链接先全源搜索，旧记录缺身份时仍需要首次补查。
